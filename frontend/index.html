    Untuk apa LibraryKu?

    Mencatat koleksi

    Setiap buku punya judul, penulis, kategori, tahun terbit, dan jumlah stok. Pustakawan tidak perlu lagi mencatat di buku tulis atau lembar kerja terpisah.

    Mencari dengan cepat

    Pengunjung membuka Katalog, mengetik judul atau nama penulis, lalu menyaring berdasarkan kategori. Stok setiap buku terlihat langsung.

    Mengelola di Dashboard

    Menambah, mengubah, dan menghapus buku dipusatkan di halaman Dashboard, terpisah dari halaman yang dilihat pengunjung.

    Dua database

    Koleksi SQL (PostgreSQL) dan NoSQL (MongoDB) disimpan terpisah. Pilih salah satu di Katalog atau Dashboard, lalu bandingkan cara kerjanya.

      Tentang LibraryKu

      Aplikasi pengelolaan perpustakaan untuk Project 1 mata kuliah Cloud Computing.

      Tujuan

      LibraryKu dibuat untuk mempraktikkan aplikasi web berbasis container: operasi CRUD (tambah, baca, ubah, hapus) yang dijalankan secara lokal memakai Docker Compose. Studi kasusnya perpustakaan dan platformnya Docker. Mode SQL memakai PostgreSQL, mode NoSQL memakai MongoDB. Penugasan resmi memakai satu kombinasi kasus per kelompok; mode NoSQL adalah pengembangan tambahan yang dapat didemonstrasikan terpisah.

      Fitur utama

      • Beranda: ringkasan koleksi dan buku terbaru dari database.
      • Katalog: cari berdasarkan judul atau penulis, saring berdasarkan kategori, lihat tahun terbit dan stok.
      • Dashboard: tambah, ubah, dan hapus buku, dengan validasi input dan konfirmasi hapus.
      • Pilihan database: SQL (PostgreSQL) atau NoSQL (MongoDB), dengan indikator database aktif.
      • Perbandingan: data nyata dari kedua database dan perbedaan cara kerjanya.

      Teknologi

      Frontend
      HTML, CSS, JavaScript biasa (tanpa framework)
      Web server
      Nginx
      Backend
      Dua layanan Flask (Python): SQL dan NoSQL, REST API berformat JSON
      Database
      PostgreSQL 16 (SQL) dan MongoDB 7.0 (NoSQL)
      Orkestrasi
      Docker Compose

      Peran Docker Compose

      Satu berkas compose.yaml mendefinisikan lima service (frontend, backend SQL, PostgreSQL, backend NoSQL, MongoDB), dua jaringan, dan dua volume. Compose menyalakan database lebih dulu, menunggu health check, lalu backend. Data buku tetap ada saat container dihentikan dan dinyalakan lagi, selama volume tidak dihapus.

      Coba API langsung

      Alamat GET bisa dibuka di browser. POST, PUT, dan DELETE diuji lewat Postman atau curl.

      • GET/api/sql/healthStatus API dan koneksi PostgreSQL
      • GET/api/nosql/healthStatus API dan koneksi MongoDB
      • GET/api/sql/booksDaftar buku di PostgreSQL (JSON)
      • GET/api/nosql/booksDaftar buku di MongoDB (JSON)
      • GET/api/{sql|nosql}/books/{id}Satu buku berdasarkan id
      • POST/api/{sql|nosql}/booksTambah buku (badan JSON)
      • PUT/api/{sql|nosql}/books/{id}Ubah data buku
      • DELETE/api/{sql|nosql}/books/{id}Hapus buku
      • GET/api/booksAlamat lama, tetap ke PostgreSQL (kompatibilitas)
